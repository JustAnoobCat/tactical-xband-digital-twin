How blocked links are handled

When terrain cuts line of sight, the terminal stops radiating and its buffers stay queued. Tac-TAD detects the blockage 3.0 s ahead and raises priority (Φevac) to flush queues to 0 KB before cutoff.

1. Abstract and research objectives

This project implements a browser-based digital twin for studying time-division multiple access (TDMA) scheduling between an aerial communication node (ACN) and geographically distributed ground terminals. Its primary research question is whether a terrain-aware dynamic scheduler can use predicted link state, traffic queues, and service priority to reduce airtime assigned to unavailable links while improving delivery relative to a static allocation baseline.

The current client-side architecture uses TypeScript modules and a dedicated WebWorker for simulation updates, while the user interface presents terrain, radio-link diagnostics, queue state, scheduler allocations, and comparative metrics. The model is a controlled simulation; results depend on its terrain representation, channel approximations, traffic assumptions, and scheduler implementation.

Primary comparison: Legacy Static TDMA baseline versus the project’s Terrain-Aware Dynamic Scheduler (Tac-TAD). Comparative claims require identical scenarios, seeds, traffic inputs, stopping rules, and metric definitions.

3. Propagation and geometry models

3.1 Three-dimensional slant range and propagation delay

d₃D = √((xA − xT)² + (yA − yT)² + (zA − zT)²)
τprop = d₃D / c    ·    TA ≈ 2 d₃D / c

Coordinates must use consistent units. Timing advance is a simplified round-trip propagation alignment relation; its implementation assumptions and compatibility with the chosen radio framing must be validated separately.

3.2 Effective Earth curvature

Re′ = k Re    ;    Δh ≈ d₁ d₂ / (2 Re′)    ;    k = 4/3 (assumed)

The effective-radius approximation models nominal tropospheric refraction. It is not a substitute for location- and time-dependent refractivity profiles. The implementation should document the geometry used for d₁ and d₂ and verify units at all boundaries.

3.3 Fresnel clearance and knife-edge diffraction

r₁ = √(λ d₁ d₂ / D)    ;    λ = c / fc
ν = h · √[(2/λ)(1/d₁ + 1/d₂)]
J(ν) = 6.9 + 20 log₁₀(√((ν − 0.1)² + 1) + ν − 0.1)

The sign convention for obstacle height h must be explicit in code and tests; a single dominant-obstacle model is an approximation for complex terrain. The project’s additional rounded-crest penalty is empirical and should be reported as a project assumption, not as a universal prescribed constant.

3.4 Link budget

Documented components include free-space path loss, diffraction, gaseous attenuation, rain attenuation, antenna gains, transmit power, receiver noise, SNR, and the selected modulation/coding abstraction. A validation suite should test each term independently and compare selected cases against independently computed reference values.

4. Scheduling, traffic, and service model

The system models a nominal 20 ms superframe and 16 ground terminals. The documented traffic classes are 5QI 69 (C2/SOS), 65 (voice), 67 (video), and 70 (photo/data). Queue admission, class priority, packet expiry, and the scheduling policy jointly affect delivery metrics.

Policy/stateIntended behaviorRequired verification
Static TDMABaseline slot allocation with fixed sizing assumptions.Slot arithmetic, guard-time accounting, total-frame conservation.
Normal LOSAllocate based on eligible queued traffic and current link estimate.Queue accounting, bitrate-to-duration consistency, priority ordering.
Pre-occlusionUse predicted link transition to prioritize eligible traffic before obstruction.Look-ahead timing, deadlines, no allocation beyond frame limits.
Hard shadowAvoid allocating payload airtime to a modeled severed link.Zero/near-zero outage allocation and correct reclamation accounting.
Re-emergenceResume eligible queued traffic after link recovery.Recovery transitions, queue integrity, starvation and fairness checks.

Any use of terms such as “optimal,” “real-time,” “guaranteed,” or “standards-compliant” requires a formal definition and supporting evidence. The UI should expose decision rationale and the exact metric window behind each comparative KPI.

7. Reproducibility protocol

  1. Record the Git commit, dependency lockfile, runtime versions, host CPU/OS, and relevant hardware configuration.
  2. Store a complete scenario configuration, terrain asset checksum, random seed, simulation duration, scheduler policy, and traffic profile.
  3. Run Static TDMA and Tac-TAD on paired inputs; do not change scenario parameters between arms.
  4. Save raw per-run metrics and event traces before aggregation. Retain failed runs and document exclusion rules.
  5. Compute confidence intervals and distributions across seeds; report sample counts and uncertainty, not only a single favorable run.
  6. Generate tables and figures programmatically from the saved outputs, then link each displayed result to its run manifest.

Recommended deliverables are a machine-readable run manifest, raw metrics CSV/JSON, test log, benchmark report, figures, and a concise limitations statement.

8. Limitations and future work

  • Terrain, weather, propagation, antenna, interference, and mobility models are abstractions; the simulation is not a substitute for field measurements.
  • A dominant-obstacle approximation may not capture multiple-edge diffraction, scattering, multipath, antenna pattern details, or time-varying channel effects.
  • Reported legacy Python benchmarks have not yet been established as equivalent TypeScript results.
  • Real-time suitability must be established through repeatable latency and stability measurements on a named target machine.
  • Formal claims about standards alignment require a clause-by-clause model mapping, not a reference to a standard name alone.
